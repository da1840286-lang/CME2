# Сборка для реального запуска (не для тестов)

## Секреты репозитория
`SOCIALCRAWL_API_KEY`, `OPENROUTER_API_KEY`, `HF_TOKEN`. Без любого из них шаг проверки входов остановит запуск до платных вызовов.

## Рекомендуемое меню для `stage=all`
| Поле | Значение |
|---|---|
| find_performance_order | `default` (целевой Sponsored Search; Ads Top не вызывается) |
| find_selection_mode | `product` |
| find_requests | 3–4 (выполняется не больше трёх целевых запросов) |
| find_max_ads | 3 |
| find_video_duration_range | выбор оператора; `all` не ограничивает длительность, остальные диапазоны требуют известную длительность |
| keywords | вводи нужные запросы по порядку; сначала идёт точное название оффера, затем эти ключевые слова, затем тип/категория товара; максимум три запроса |
| find_include_retention | `false` (иначе сообщается как запрошенное, но не выполняется) |
| offer_json | обязательно; факты товара и `approved_brand_marks`. Режим брендинга выбирается отдельно через меню `branding_policy`; фото задаётся отдельно в `target_photo_url` |
| Кэш подтверждения референса | включён (`CME_REFERENCE_CACHE_DIR` + actions/cache restore/save) |

## Что проверено локально
Полный offline-набор: **600 тестов пройдены, 6 пропущены**. Он проверяет меню → параметры FIND, порядок целевых запросов, допуск и handoff кандидатов, branding schema v2, обязательные визуальные атомы и правила Target-Fit. Дополнительно воспроизводятся реальные данные из GitHub Actions artifacts `41185128123`, `41148117074` и `41206920383`: реальные наблюдения видео, кандидаты FIND и ответы Brain Target-Fit. Видеоссылки и временные URL в фикстуры не попадают; провайдеры не вызываются. Эти проверки подтверждают поведение кода на зафиксированных данных, но не заменяют новый live-запуск SocialCrawl/моделей.

## Порядок первого реального запуска
1. `stage=all` с таблицей выше. Ожидаемо: до трёх целевых Sponsored Search-запросов, `CANDIDATES_FOUND`, допущенные кандидаты в `candidates.json`, `selected_candidate.json` с проверенным `source_selection` и `analysis_eligibility`.
2. Если `all` остановился на модели (502/429), повторите: FIND, выбранный кандидат и анализ воспроизводимы по
   `find_run_id` и `candidate_id`.
3. В меню `branding_policy` явно выберите `target_brand_allowed` или `no_branding`. В `offer_json` не передавайте дублирующий `branding_policy`; перечислите только подтверждённые `approved_brand_marks`.
4. Проверьте `target_fit_gate.json` (`rejection_basis: EVIDENCE_GAP` означает нехватку данных в оффере, не доказанную несовместимость).
